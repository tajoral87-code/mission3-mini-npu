# Mini NPU Simulator — 미션 3

## 1. 프로젝트 소개

Python을 이용하여 AI의 기본 계산 방식 중 하나인 MAC(Multiply-Accumulate) 연산을 구현한 프로그램입니다.

2차원 숫자 배열로 표현된 패턴과 필터를 비교하여 십자가(Cross)인지 X인지 판정하고, 배열 크기에 따른 연산 성능을 분석합니다.

## 2. 개발 환경

- Python 3.8 이상
- Visual Studio Code
- Python 표준 라이브러리: `json`, `math`, `re`, `time`
- NumPy 및 기타 외부 라이브러리 사용하지 않음

## 3. 실행 방법

`main.py`와 `data.json`을 같은 폴더에 배치합니다.

터미널에서 다음 명령어를 실행합니다.

```powershell
python main.py
```

프로그램 실행 후 다음 두 가지 모드 중 하나를 선택합니다.

- **모드 1:** 3×3 필터 A, 필터 B와 입력 패턴을 직접 입력하여 판정
- **모드 2:** `data.json`의 필터와 패턴을 불러와 자동 분석

## 4. 주요 기능

### MAC 연산

동일한 위치에 있는 패턴과 필터의 숫자를 곱한 뒤 모든 결과를 합산합니다.

Python의 중첩 `for` 반복문을 이용해 직접 구현했습니다.

### 라벨 정규화

데이터에서 사용되는 `+`, `cross`는 `Cross`로, `x`는 `X`로 변환합니다.

이를 통해 데이터에 사용된 라벨 표현과 관계없이 일관된 비교를 수행합니다.

### 부동소수점 오차 처리

두 점수의 차이가 `1e-9` 미만이면 동점으로 간주합니다.

동점은 `UNDECIDED`로 출력하며 임의로 Cross나 X로 판정하지 않습니다.

### 입력 오류 처리

3×3 사용자 입력의 행별 숫자 개수를 검사합니다.

숫자가 아닌 값을 입력하면 재입력을 요청합니다.

JSON 데이터의 배열 크기, 숫자 형식, 필터 구조, 라벨을 검증하여 잘못된 케이스를 FAIL로 처리합니다.

## 5. 결과 리포트

### 5.1 JSON 테스트 결과

| 테스트 | Cross 점수 | X 점수 | 판정 | 결과 |
|---|---:|---:|---|---|
| size_5_1 | 0.9 | 0.9 | UNDECIDED | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | PASS |
| size_13_1 | 0.3 | 14.7 | X | PASS |
| size_13_2 | 7.5 | 7.5 | UNDECIDED | FAIL |
| size_25_1 | 4.9 | 4.9 | UNDECIDED | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | PASS |

- 전체 테스트: 6개
- 통과: 3개
- 실패: 3개

### 5.2 실패 원인 분석

1. `size_5_1`은 Cross와 X 점수가 모두 0.9로 계산되어 동점입니다.
2. 해당 데이터의 expected는 X이지만, 프로그램은 동점 규칙에 따라 UNDECIDED로 판정합니다.
3. `size_13_2`는 Cross와 X 점수가 모두 7.5이므로 동점입니다.
4. 해당 데이터의 expected는 Cross이지만, 프로그램은 UNDECIDED로 판정합니다.
5. `size_25_1`도 두 필터의 점수가 모두 4.9로 계산됩니다.
6. 해당 데이터의 expected는 X이지만, 프로그램은 UNDECIDED로 판정합니다.
7. 세 실패 모두 프로그램이 중단되거나 예외가 발생해서 생긴 실패가 아닙니다.
8. 문제의 원인은 제공된 필터와 패턴의 MAC 점수가 동점인데 expected에는 특정 라벨이 지정되어 있기 때문입니다.
9. 라벨 정규화 기능은 정상적으로 적용되어 `+`와 `x`를 표준 라벨로 변환합니다.
10. epsilon 정책은 부동소수점의 미세한 오차 때문에 동점을 잘못 판별하는 문제를 줄입니다.
11. 정규화와 epsilon 처리가 모두 정상 작동해도 실제 점수가 동점이면 FAIL이 발생할 수 있습니다.
12. 따라서 원본 데이터를 임의로 변경하거나 동점을 특정 라벨로 강제 판정하지 않았습니다.
13. 오류 원인을 데이터/스키마 문제, 계산 로직 문제, 수치 비교 문제로 구분하여 진단했습니다.
14. 이번 원본 데이터의 세 실패는 동점 판정 정책과 expected 라벨의 불일치로 설명할 수 있습니다.

### 5.3 성능 분석

MAC 함수를 각 크기별로 10회 반복 실행하고 평균 실행 시간을 밀리초(ms) 단위로 측정합니다.

입력과 출력, JSON 파일 읽기 시간은 측정에서 제외합니다.

| 배열 크기 | 위치별 곱셈 횟수 | 평균 연산 시간 |
|---|---:|---|
| 3×3 | 9 | 실행 결과 참조 |
| 5×5 | 25 | 실행 결과 참조 |
| 13×13 | 169 | 실행 결과 참조 |
| 25×25 | 625 | 실행 결과 참조 |

### 5.4 시간 복잡도 분석

1. MAC 연산은 입력 배열의 모든 위치를 확인해야 합니다.
2. N×N 배열에는 N²개의 숫자 위치가 존재합니다.
3. 프로그램은 중첩 반복문을 이용해 모든 위치를 방문합니다.
4. 각 위치에서는 숫자 두 개를 곱하고 결과를 누적합니다.
5. 따라서 MAC 함수의 시간 복잡도는 **O(N²)**입니다.
6. 3×3 배열은 9번, 25×25 배열은 625번의 위치별 곱셈을 수행합니다.
7. 배열의 한 변이 증가하면 연산 횟수는 그 크기의 제곱에 비례하여 증가합니다.
8. 실제 실행 시간은 CPU 상태, Python 실행 환경, 측정 오차의 영향을 받습니다.
9. 특히 연산 시간이 매우 짧은 경우에는 반복 측정 평균에도 오차가 남을 수 있습니다.
10. 따라서 실행 시간만이 아니라 이론적 연산 횟수를 함께 확인하여 O(N²)의 근거를 분석했습니다.

## 6. 결론

이번 프로젝트를 통해 AI 연산의 기초인 MAC 계산을 Python 반복문으로 구현했습니다.

직접 입력한 3×3 패턴뿐 아니라 JSON 파일의 다양한 크기까지 처리할 수 있도록 설계했습니다.

라벨 정규화, epsilon 동점 정책, 데이터 검증과 실패 원인 분석의 중요성을 확인했습니다.

또한 배열 크기에 따라 계산량이 증가하는 이유를 이해하고, AI 전용 연산 장치에서 병렬 처리가 중요한 배경을 학습했습니다.
