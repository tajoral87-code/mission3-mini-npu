# Mini NPU Simulator — 미션 3

## 1. 프로젝트 소개

Python을 이용하여 AI의 기본 계산 방식 중 하나인 MAC(Multiply-Accumulate) 연산을 구현한 프로그램입니다.

2차원 숫자 배열로 표현된 패턴과 필터를 비교하여 십자가(Cross)인지 X인지 판정하고, 배열 크기에 따른 연산 성능을 분석합니다.

## 2. 개발 환경

- Python 3.8 이상
- Visual Studio Code
- Python 표준 라이브러리: `json`, `math`, `re`, `time`
- NumPy 및 기타 외부 라이브러리 사용하지 않음

## 3. 실행 방법

`main.py`와 `data.json`을 같은 폴더에 배치합니다.

터미널에서 다음 명령어를 실행합니다.

```powershell
python main.py
```

프로그램 실행 후 다음 두 가지 모드 중 하나를 선택합니다.

- **모드 1:** 3×3 필터 A, 필터 B와 입력 패턴을 직접 입력하여 판정
- **모드 2:** `data.json`의 필터와 패턴을 불러와 자동 분석

## 4. 주요 기능

### MAC 연산

동일한 위치에 있는 패턴과 필터의 숫자를 곱한 뒤 모든 결과를 합산합니다.

Python의 중첩 `for` 반복문을 이용해 직접 구현했습니다.


### MAC 점수와 유사도의 관계

MAC 점수는 입력 패턴과 필터의 같은 위치에 있는
숫자들을 곱한 뒤 모두 더한 결과입니다.

**이번 시뮬레이터에서는 동일한 입력 패턴에 대해
MAC 점수가 높은 필터일수록 입력 패턴과의 유사도가
높다고 해석합니다.**

예를 들어 3×3 십자가 패턴을 입력했을 때
십자가 필터의 MAC 점수가 5점이고
X 필터의 점수가 1점이라면
십자가 필터와 더 유사하다고 판정합니다.

단, MAC 점수는 정규화된 유사도 지표가 아닙니다.
필터의 숫자 크기나 가중치에 영향을 받으므로
일반적으로 점수가 높다는 이유만으로
형태가 반드시 더 유사하다고 단정할 수는 없습니다.

이번 프로그램은 제공된 필터를 사용하는
단순한 MAC 점수 기반 패턴 분류기입니다.


### 라벨 정규화

데이터에서 사용되는 `+`, `cross`는 `Cross`로, `x`는 `X`로 변환합니다.

이를 통해 데이터에 사용된 라벨 표현과 관계없이 일관된 비교를 수행합니다.

### 부동소수점 오차 처리

두 점수의 차이가 `1e-9` 미만이면 동점으로 간주합니다.

동점은 `UNDECIDED`로 출력하며 임의로 Cross나 X로 판정하지 않습니다.

### 입력 오류 처리

3×3 사용자 입력의 행별 숫자 개수를 검사합니다.

숫자가 아닌 값을 입력하면 재입력을 요청합니다.

JSON 데이터의 배열 크기, 숫자 형식, 필터 구조, 라벨을 검증하여 잘못된 케이스를 FAIL로 처리합니다.

## 5. 결과 리포트

### 5.1 JSON 테스트 결과

| 테스트 | Cross 점수 | X 점수 | 판정 | 결과 |
|---|---:|---:|---|---|
| size_5_1 | 0.9 | 0.9 | UNDECIDED | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | PASS |
| size_13_1 | 0.3 | 14.7 | X | PASS |
| size_13_2 | 7.5 | 7.5 | UNDECIDED | FAIL |
| size_25_1 | 4.9 | 4.9 | UNDECIDED | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | PASS |

- 전체 테스트: 6개
- 통과: 3개
- 실패: 3개

### 5.2 실패 원인 분석

1. `size_5_1`은 Cross와 X 점수가 모두 0.9로 계산되어 동점입니다.
2. 해당 데이터의 expected는 X이지만, 프로그램은 동점 규칙에 따라 UNDECIDED로 판정합니다.
3. `size_13_2`는 Cross와 X 점수가 모두 7.5이므로 동점입니다.
4. 해당 데이터의 expected는 Cross이지만, 프로그램은 UNDECIDED로 판정합니다.
5. `size_25_1`도 두 필터의 점수가 모두 4.9로 계산됩니다.
6. 해당 데이터의 expected는 X이지만, 프로그램은 UNDECIDED로 판정합니다.
7. 세 실패 모두 프로그램이 중단되거나 예외가 발생해서 생긴 실패가 아닙니다.
8. 문제의 원인은 제공된 필터와 패턴의 MAC 점수가 동점인데 expected에는 특정 라벨이 지정되어 있기 때문입니다.
9. 라벨 정규화 기능은 정상적으로 적용되어 `+`와 `x`를 표준 라벨로 변환합니다.
10. epsilon 정책은 부동소수점의 미세한 오차 때문에 동점을 잘못 판별하는 문제를 줄입니다.
11. 정규화와 epsilon 처리가 모두 정상 작동해도 실제 점수가 동점이면 FAIL이 발생할 수 있습니다.
12. 따라서 원본 데이터를 임의로 변경하거나 동점을 특정 라벨로 강제 판정하지 않았습니다.
13. 오류 원인을 데이터/스키마 문제, 계산 로직 문제, 수치 비교 문제로 구분하여 진단했습니다.
14. 이번 원본 데이터의 세 실패는 동점 판정 정책과 expected 라벨의 불일치로 설명할 수 있습니다.

### 5.3 성능 분석

MAC 함수를 각 크기별로 10회 반복 실행하고 평균 실행 시간을 밀리초(ms) 단위로 측정합니다.

입력과 출력, JSON 파일 읽기 시간은 측정에서 제외합니다.


| 배열 크기 | 위치별 곱셈 횟수 | 평균 연산 시간(ms) |
|---|---:|---:|
| 3×3 | 9 | 0.001290 |
| 5×5 | 25 | 0.002440 |
| 13×13 | 169 | 0.013210 |
| 25×25 | 625 | 0.041350 |


### 5.4 시간 복잡도 분석

1. MAC 연산은 입력 배열의 모든 위치를 확인해야 합니다.
2. N×N 배열에는 N²개의 숫자 위치가 존재합니다.
3. 프로그램은 중첩 반복문을 이용해 모든 위치를 방문합니다.
4. 각 위치에서는 숫자 두 개를 곱하고 결과를 누적합니다.
5. 따라서 MAC 함수의 시간 복잡도는 **O(N²)**입니다.
6. 3×3 배열은 9번, 25×25 배열은 625번의 위치별 곱셈을 수행합니다.
7. 배열의 한 변이 증가하면 연산 횟수는 그 크기의 제곱에 비례하여 증가합니다.
8. 실제 실행 시간은 CPU 상태, Python 실행 환경, 측정 오차의 영향을 받습니다.
9. 특히 연산 시간이 매우 짧은 경우에는 반복 측정 평균에도 오차가 남을 수 있습니다.
10. 따라서 실행 시간만이 아니라 이론적 연산 횟수를 함께 확인하여 O(N²)의 근거를 분석했습니다.

## 6. 결론

이번 프로젝트를 통해 AI 연산의 기초인 MAC 계산을 Python 반복문으로 구현했습니다.

직접 입력한 3×3 패턴뿐 아니라 JSON 파일의 다양한 크기까지 처리할 수 있도록 설계했습니다.

라벨 정규화, epsilon 동점 정책, 데이터 검증과 실패 원인 분석의 중요성을 확인했습니다.

또한 배열 크기에 따라 계산량이 증가하는 이유를 이해하고, AI 전용 연산 장치에서 병렬 처리가 중요한 배경을 학습했습니다.


## 7. 보너스 과제 결과

### 7.1 메모리 접근 최적화 (2D vs 1D)

2차원 배열을 1차원 배열로 변환하는
flatten_matrix() 함수를 구현했습니다.

1차원 배열을 순차적으로 접근하는
mac_flat() 함수를 추가했습니다.

동일한 입력과 반복 횟수(10회)를 사용해
기존 2차원 MAC 함수와 실행 속도를 비교했습니다.

| 크기 | 2D 평균(ms) | 1D 평균(ms) | 점수 검증 |
|---|---:|---:|---|
| 3×3 | 0.001300 | 0.000820 | PASS |
| 5×5 | 0.002460 | 0.001440 | PASS |
| 13×13 | 0.012170 | 0.008000 | PASS |
| 25×25 | 0.041570 | 0.032140 | PASS |

모든 배열 크기에서 두 방식의 MAC 점수가
epsilon(1e-9) 이내로 일치했습니다.

이번 측정에서는 1차원 배열 방식이
모든 크기에서 더 빠르게 실행되었습니다.

단, 배열 변환 시간은 측정하지 않았으므로
전체 처리 시간이 반드시 더 빠르다는 의미는 아닙니다.

### 7.2 패턴 자동 생성기

create_cross()와 create_x() 함수를 구현했습니다.

사용자가 N을 입력하면 N×N 크기의
십자가와 X 패턴을 자동으로 생성합니다.

지원 크기는 3부터 25까지의 홀수입니다.

5×5 패턴 생성 및 판정 테스트 결과:

- Cross 필터 점수: 9.0
- X 필터 점수: 1.0
- 판정 결과: Cross
- 테스트 결과: PASS

생성된 패턴은 MAC 연산 및 성능 분석에
재사용할 수 있도록 구현했습니다.

### 7.3 종합 평가

두 가지 보너스 기능이 모두 정상 작동했습니다.

1차원 배열의 계산 결과가 기존 2차원 방식과
일치함을 확인했으며, 실제 성능 차이도 측정했습니다.

패턴 자동 생성기를 통해 사용자가 숫자 배열을
직접 작성하지 않고도 MAC 연산을 시험할 수 있습니다.


## 8. AI 사전평가 보완 사항

### 8.1 모드별 동점 처리 규칙

두 모드 모두 MAC 점수 차이가 epsilon(1e-9) 미만이면
동점으로 판단합니다.

| 구분 | 내부 판정 | 사용자 출력 |
|---|---|---|
| 모드 1 | UNDECIDED | 판정 불가 (동점) |
| 모드 2 | UNDECIDED | UNDECIDED |

모드 1은 사용자가 직접 입력한 필터 A/B를 비교하므로
한글로 '판정 불가'를 출력합니다.

모드 2는 JSON의 표준 라벨 Cross/X를 사용하므로
동점 결과를 UNDECIDED로 출력합니다.

두 모드의 판단 기준은 같고 출력 표현만 다릅니다.

### 8.2 새로운 라벨을 추가하는 절차

현재 표준 라벨은 Cross와 X 두 종류입니다.

새로운 라벨을 지원할 때는 다음 절차를 따릅니다.

1. normalize_label() 함수에 새 라벨 변환 규칙을 추가합니다.
2. 필터를 읽는 부분에서 새 라벨을 허용하도록 수정합니다.
3. 필요하면 두 필터만 비교하는 판정 구조를 확장합니다.
4. 정상 라벨과 잘못된 라벨에 대한 테스트를 추가합니다.
5. README에 변경한 라벨 규칙과 사용 예시를 기록합니다.
6. 기존 Cross/X 테스트가 정상인지 회귀 테스트를 실행합니다.

단순한 별칭 추가라면 normalize_label() 변경만으로
처리할 수 있는 경우도 있습니다.

하지만 새로운 패턴 종류를 추가하는 경우에는
필터 선택 및 판정 구조까지 변경해야 합니다.

### 8.3 대형 배열 처리와 확장 전략

현재 프로그램은 최대 25x25 크기의 패턴을 대상으로
성능을 측정합니다.

1000x1000 배열을 처리한다면
하나의 배열에 1,000,000개의 값이 필요합니다.

MAC 연산도 필터 한 개당 1,000,000번의
위치별 곱셈과 누적 덧셈을 수행합니다.

1000x1000 배열은 25x25 배열보다
위치별 연산 횟수가 1600배 많습니다.

데이터를 64비트 실수로 연속 저장한다고 가정하면
배열 하나의 원시 숫자 데이터는 약 8MB입니다.

그러나 Python의 2차원 리스트는 리스트 구조와
객체 참조 등에 추가 메모리를 사용합니다.
실제 메모리 사용량은 데이터 표현에 따라 달라집니다.

대형 입력을 처리할 때 예상되는 문제는 다음과 같습니다.

- 반복문 실행 시간 증가
- 메모리 사용량 증가
- 캐시 효율과 메모리 접근 비용 문제
- 대량 데이터 복사 및 변환 비용

우선 적용할 개선 전략은 다음과 같습니다.

1. 중첩 리스트와 1차원 배열의 처리 성능을 비교합니다.
2. 불필요한 배열 복사와 중복 계산을 줄입니다.
3. 큰 배열을 작은 블록 단위로 처리하는 방식을 검토합니다.
4. 메모리 사용량과 연산 시간을 각각 측정합니다.
5. 병렬 처리나 전용 연산 장치의 활용을 검토합니다.

현재 보너스 1은 배열을 미리 변환한 뒤
MAC 계산 시간만 비교하는 실험입니다.

따라서 배열 변환 비용까지 포함한
전체 처리 성능과는 구분해야 합니다.

### 8.4 CPU와 NPU의 병목 비교

CPU는 다양한 종류의 명령어와 복잡한 제어 흐름을
처리할 수 있는 범용 프로세서입니다.

CPU도 여러 코어와 SIMD 명령어를 통해
병렬 연산이 가능합니다.

하지만 Python의 일반적인 중첩 반복문은
대규모 MAC 계산에 최적화되어 있지 않습니다.

NPU는 신경망에서 많이 사용하는 곱셈과
누적 덧셈 연산을 대규모로 병렬 처리하도록 설계됩니다.

| 비교 항목 | CPU | NPU |
|---|---|---|
| 주요 목적 | 범용 계산 | 신경망 연산 가속 |
| MAC 처리 | 범용 실행 자원 활용 | 다수의 MAC 연산기 활용 |
| 병렬 처리 | 멀티코어 및 SIMD | 대규모 병렬 연산 구조 |
| 대표적 병목 | 명령어 처리, 캐시, 메모리 접근 | 데이터 공급, 메모리 대역폭, 데이터 이동 |
| 작은 작업 | 유연하고 효율적일 수 있음 | 초기화·전송 비용이 불리할 수 있음 |

NPU에 연산기가 많더라도 필요한 데이터를
충분히 빠르게 공급하지 못하면 성능이 떨어집니다.

이것을 메모리 대역폭 병목이라고 합니다.

또한 데이터를 CPU에서 NPU로 이동하는 시간,
작업을 시작할 때 발생하는 지연시간(latency),
연산기 활용률도 실제 성능에 영향을 줍니다.

따라서 NPU가 모든 계산에서 CPU보다
무조건 빠르다는 의미는 아닙니다.
